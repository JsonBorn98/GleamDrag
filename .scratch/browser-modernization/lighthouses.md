## Lighthouses
- [WXT 多浏览器构建与 Manifest 目标](https://github.com/wxt-dev/wxt/blob/main/docs/guide/essentials/target-different-browsers.md) — 2026-09-16 核对官方源码与文档：WXT 可生成不同浏览器/Manifest 产物，Firefox 默认仍为 MV2，如选择 MV3 必须显式设置；框架只能集中构建分歧，不能替代运行时能力适配。作为 GleamDrag 局部重构构建候选的外部参考，尚未决定采用。
- [WXT Content Script 生命周期与 Shadow Root UI](https://github.com/wxt-dev/wxt/blob/main/docs/guide/essentials/content-scripts.md) — 2026-09-16 读取官方文档：context 可统一清理失效的 content script 监听器、定时器及动画回调；Shadow Root UI 支持样式隔离但 rem 仍受宿主根字号影响。用于比较现有 UI proxy 与生命周期管理，不视为解决宿主 CSP 或用户脚本执行的通用办法；MAIN world 支持范围须另以浏览器官方文档核实。
- [Playwright 扩展测试并非三浏览器通用路径](https://github.com/microsoft/playwright/blob/main/docs/src/chrome-extensions-js-python.md) — 2026-09-16 核对官方文档：扩展加载路径只支持 Chromium 的 persistent context；当前 Chrome/Edge 已移除相关命令行 sideload flags，文档建议 Playwright 自带 Chromium。故 Chromium 自动测试不能声明完成真实 Chrome、Edge、Firefox 扩展验收，须保留各浏览器实际安装运行路径。
- [MV3 的后台生命周期与用户脚本能力差异](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/userScripts) — 2026-09-16 核对 MDN 与 Chrome 文档：Firefox MV3 用非持久 background scripts，Chromium 用 service_worker，可分别生成 manifest；监听器须同步注册。用户脚本应区分预打包 scripting 执行与用户代码 userScripts，Firefox optional_permissions 与 Chromium 权限/用户开关不同；register 与 execute 不能视为同样可用，尤其即时执行须能力检测及当前稳定版验证。
- [WXT、Svelte 与 Vite 的版本兼容约束](https://github.com/wxt-dev/wxt/blob/main/packages/module-svelte/package.json) — 2026-09-16 核对官方主分支 package.json：@wxt-dev/module-svelte 2.x 要求 Svelte>=5；WXT 0.21.4 声明 Vite 6.3.4/7/8 支持、Bun>=1.2、Node>=22。因此不能推荐迁入当前 WXT Svelte module 却原封不动保留 Svelte3 runtime。可保留旧语法逐步兼容迁移，或先修现有构建。实施时须按锁定release重验peerDependencies，不能仅用主分支声明当组合构建通过。
