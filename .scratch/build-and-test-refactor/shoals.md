- [Svelte 5 custom element 惰性挂载：connectedCallback 微任务后才有导出方法，先调后 append 直接 TypeError](C:/Users/lijso/Desktop/VibeCode/GleamDrag/src/components/indicator/indicator.ts) — Svelte 3 的 custom element 在构造函数里急切挂载组件实例（k(this, {target: this.shadowRoot, ...})），elem.show() 在 append 之前就能调；Svelte 5 改成 connectedCallback 里 await Promise.resolve() 之后才 createClassComponent，导出方法（show/reset/box）的 getter 全部走 this.$$c?.[prop]——$$c 挂载前是 undefined，elem.show() 抛「not a function」。迁移修法：wrapper 先 append（触发 connectedCallback 排进微任务队列），再 queueMicrotask 把导出调用排到挂载之后（微任务 FIFO 保证挂载先于调用）；hide 里的 reset 同理且要加 isConnected 守卫防止 remove 后调用。票 07 之后任何直接调用 .svelte 导出方法/常量的新代码都要过这个 gate，别照 Svelte 3 习惯在 append 前调导出。

- [Vitest CLI 过滤器穿不透 config exclude：「No test files found」退出 1 是假红](C:/Users/runzhe.li/Desktop/VibeCode/GleamDrag/scripts/verify_vitest_exit_code.mjs) — vitest run <path-filter> 只是过滤 include 的命中集，config test.exclude 里列出的文件无论 CLI 传什么都跑不到；被 exclude 的文件传了过滤器，vitest 报 No test files found, exiting with code 1——退出码是非零，但没跑任何测试。若把非零退出码当「失败用例被验证」，就是在验证一个空集：这是本 feature 一路的假绿/假红主题（cli.mjs 误读 failure 字段、CI 从不跑测试）在 Vitest 栈的变体。修法：故意失败 fixture 配专用最小 config（include 直接点名 fixture），验证脚本里 red leg 除断言非零退出外还要断言输出里真的出现 fixture 测试名——「No test files found」也退出 1，非零本身不构成证据。票 09 CI 引 Vitest 时沿用这两个断言（exit code + 输出含测试名），别只看退出码。
