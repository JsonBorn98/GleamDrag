## Shoals
- [pnpm 11 ignored-builds 劫持本机所有 pnpm exec 退出码（exit 1 ≠ 命令失败）](C:/Users/runzhe.li/Desktop/VibeCode/GleamDrag/scripts/cli.mjs) — 本机 pnpm 11 的 deps status check 因 ignored build scripts（core-js/dtrace-provider/spawn-sync/svelte-preprocess）在每次 `pnpm exec <cmd>` 前置检查时 exit 1——输出先打 "Lockfile is up to date" 再报 ERR_PNPM_IGNORED_BUILDS，命令本体根本没跑。这不是命令失败，是 pnpm 劫持了退出码：cli.mjs 的 `spawn("pnpm", ["exec", "web-ext", ...])` 与任何 `pnpm exec`/`pnpm run` 路径在本机都会拿到 exit 1。修法二选一：跑 `pnpm approve-builds` 一次性放行（或 pnpm config set enable-pre-post-scripts），或像本票 verify_exit_code.mjs 一样绕开 pnpm 直接调 node_modules 下的 bin（node node_modules/typescript/bin/tsc 先例）。票 02/03 会话在本机起 web-ext/跑命令前先处理这个，别把 exit 1 误判成命令失败。

- [web-ext 7.6.2 在 Windows 把反斜杠 Firefox 路径吞成转义符（ENOENT 陷阱）](C:/Users/runzhe.li/Desktop/VibeCode/GleamDrag/scripts/utils.mjs) — 给 `web-ext run -f` 传 Windows 反斜杠路径（如 `C:\Program Files\...\firefox.exe`）时，fx-runner 内部经 shell-quote 解析，`\P` 变 P、`\f` 变换页符，spawn 目标变成 `C:Program FilesMozilla Firefox<FF>irefox.exe`，ENOENT 且是 unhandled 'error' 事件直接崩进程。路径统一转正斜杠（`split(pathLib.sep).join("/")`）即好——Node 与 Firefox 都接受正斜杠。票 05 WXT 迁移后若换 web-ext 版本，先验证这条。
- [commander 的 --no-<x> 选项显式传默认值 false 会把该布尔永久钉死](C:/Users/runzhe.li/Desktop/VibeCode/GleamDrag/scripts/cli.mjs) — `.option('--no-browser', desc, false)`：commander 对 --no-x 本来默认 true、传 --no-x 时翻成 false；但第三个参数显式给了 false 就成了无条件默认，args.browser 永远 false → runBrowser 从不执行 → wss 等事件等到永远。表象是「cli 起了 wss 占住端口却无任何子进程、零输出僵尸」，还连带下个进程 EADDRINUSE。修法：--no-x 选项永远不要显式传默认值。票 09 CI 会复用 --no-browser 语义，注意别再传默认值。
